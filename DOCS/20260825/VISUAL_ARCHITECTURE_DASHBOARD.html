Overview

Tier 1 · 30-second read

A self-contained WinUI 3 desktop app that splits recordings into one clip per take and turns webcam frames into background-free head shots — entirely on the machine. Three source projects with a strictly one-way dependency chain, two vertical slices that never reference each other, and a failure model that returns reasons instead of throwing. There is no server, no database, no authentication and no network call anywhere in the source.

Domain ERD — entities, DTOs and value objects

Records, not classes

Every contract in Shared is a sealed record with init-only properties and real defaults, so an options object built with no arguments is already the sensible one. ExportOptions.PassThrough is the extreme case: an export with nothing set is a bit-for-bit plain slice, which is the guarantee the app started with.

Derived properties carry meaning

ExportOptions.IsPassThrough is not a convenience — it selects the fast path in ClipExporter that skips the measuring pass entirely. CutoutFileItem.IsReady gates the save buttons. Both are computed, never stored, so they cannot drift.

Narrative — how the pieces actually behave

Filtered by the Narrative filter control at the top of the page.

The camera is a frame reader, not a capture element

WinUI 3 ships no CaptureElement — that was UWP. The viewfinder is built by pushing MediaFrameReader frames into a SoftwareBitmapSource. Stills come from the most recent preview frame because CapturePhotoToStreamAsync fights the frame reader for the device on many webcams.

Dropping frames is the correct behaviour

CutoutPage guards with Interlocked.CompareExchange and discards any frame arriving while the previous one is still being handed to the UI thread. Without it the queue grows without bound and the preview drifts seconds behind the room. Only the newest frame is worth showing.

u2netp finds a person, not a head

It is a saliency model, so its alpha bounding box always includes the shoulders. HeadFinder narrows it by reading per-row mask widths: the head widens to a peak (cheekbones), narrows to the neck, then the shoulders flare back out. All three must hold — a head-only photo has no flare and keeps its full height rather than being cut in half by a fixed proportion.

Hard edge removes the halo; threshold alone does not

Thresholding deletes the faint pixels but leaves everything above the cut translucent, which reads as a glow around hair. HardEdge snaps every survivor to fully opaque, turning the soft saliency map into a clean stencil. That is why the page ships it on by default with a 1 px erode.

The detector refuses to guess a threshold

It sweeps every gate from noiseFloor + 3 dB to peak − 3 dB in 0.5 dB steps, counts the takes each gate produces, and keeps the centre of the widest band of gates that agree on the expected count. Below 6 dB of contrast between loudest and quietest it declares there is no split to make.

Normalization reads each clip twice, on purpose

The whole clip must be measured before the first sample can be written, so ClipExporter reads the slice once to measure and once to write. Reading twice rather than buffering keeps memory flat whether the take is 200 ms or the entire recording. An export with no options set skips the measuring pass entirely.

Three guards stop normalization lying

ClipProcessor.DecideGain applies them in order: a clip below −70 dB is silence and is left alone; gain is reduced if it would breach the ceiling, so a loudness target is never met by clipping; and gain is capped at 24 dB, because targeting −16 LUFS on a clip of room tone would otherwise raise the noise by 40 dB and call it a take.

The loudness meter uses the analog prototype, not the cookbook

LoudnessMeter’s K-weighting shelf is derived by bilinear-transforming the BS.1770 analog prototype. The RBJ cookbook shelf is a different filter — it lands the poles elsewhere and reads about 0.25 LU low. This derivation reproduces the standard’s coefficient table exactly at 48 kHz and stays correct at every other rate, which matters because clips keep their source rate.

A flat ZIP cannot afford a name collision

ClipExporter.UniqueStems gives every source a distinct, case-insensitively unique stem — two uploads called Nick_Happy.m4a become Nick_Happy and Nick_Happy(2) — so the archive reads like the output folder and no clip is silently dropped on Windows.

Optional capabilities degrade, they never throw

Probe, report, degrade. The ONNX model, the camera, the microphone and the platform audio codecs all follow it: u2netp.onnx missing drops the engine and shows a banner; MediaCapture failing returns false and a sentence; AudioDecoder.IsSupportedExtension reports a shorter list off Windows. The capability disappears from the UI instead of breaking it.

Long work must not run on the UI thread

Analyze, GetClip and the ZIP builders are deliberately synchronous so the caller must decide where they run. The view models call them through Task.Run. Making them async would hide, not solve, the fact that the work stays on the calling thread.

Run from bin, never from publish

dotnet publish silently drops PoChopAudio.WinUI.pri, the app’s own resource index, and without it the app dies at startup with a stowed exception (0xC000027B) inside Microsoft.UI.Xaml.dll. The build output has the .pri plus every self-contained Windows App SDK file. The app ships the SDK runtime because an unpackaged app without it fails with 0x80670016.

Each store owns a private scratch directory

An earlier version wiped %TEMP%/PoChopAudio outright on construction, so a second instance deleted the first one’s audio out from under it. Now each store creates its own GUID subdirectory and only sweeps siblings older than the two-hour job lifetime — age being the only safe signal that a sibling is abandoned rather than live.

Failures are values, not exceptions

Outcome<T> carries a value or one of seven domain reasons. An expired job is not exceptional. The conversion to an exception happens only in the view models, via .OrThrow(), which lives in WinUI and must never move into Services.
