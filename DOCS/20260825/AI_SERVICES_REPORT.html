AI Services Report

Every inference this application performs runs on the local CPU, from a single 4.4 MB ONNX file, at a marginal cost of zero. This report maps the one model, the code that binds it, the payload it receives, and what happens when it is absent.

Scope correction

The NET_DOCS template assumes hosted, metered AI services configured through an AiPricing section. No such configuration exists in this repository — a case-insensitive search for AiPricing across all .cs, .csproj and .json sources returns nothing, and Directory.Packages.props pins no SDK for any model provider. This report therefore documents the inference surface that does exist: one in-process ONNX Runtime session. AGENT.md records the decision explicitly — “No paid AI services. Both engines are free (on-device ONNX models). remove.bg was considered and dropped per the no-paid-services decision.”

Tier 1 · Executive summary

30-second read

One model, one engine, zero dollars, zero bytes off the machine. The Cutout feature runs u2netp.onnx — a small U²-Net saliency network — through Microsoft.ML.OnnxRuntime in the app’s own process. There is no API key, no token meter, no rate limit and no network dependency at inference time. The only variable cost is CPU time, bounded to half the machine’s logical cores.

The model file is not in the repository. A fresh clone has no cutout capability at all; the app detects this, drops the engine from its list, and shows a banner rather than failing. That is the deliberate probe, report, degrade pattern, and it is the single most important operational fact in this document.

Tier 2 · Architecture

The inference path is four hops deep and crosses exactly one project boundary. The view model never names an engine implementation; it names an enum value, and EnginePicker resolves that to whatever is actually loadable on this machine.

Why the indirection exists

EnginePicker is constructed from IEnumerable<IBackgroundRemover> and immediately filters on r.IsAvailable. An engine whose model file is missing never enters the dictionary, so AvailableEngines is a truthful runtime list rather than a compile-time one. CutoutService.IsAvailable is simply picker.AvailableEngines.Count > 0, and the Cutout page binds a banner to it. This is what lets a fresh clone build, launch and run every other feature with no model present.

Vestigial surface worth knowing about

CutoutEngine.BrowserOnnx and the IBackgroundRemover doc-comment’s reference to “server-side (OnnxU2Net, RemoveBg) or client-side (BrowserOnnx)” are leftovers from the deleted Blazor client. CutoutService.Validate still accepts Engine = BrowserOnnx as valid input; EnginePicker then silently substitutes OnnxU2Net. The substitution is safe, but a caller asking for BrowserOnnx receives no signal that it did not get what it asked for. EnginePicker’s own warning string also still mentions /api/cutout endpoints returning 503 — endpoints that no longer exist.

Inference payload — the exact contract

The model is not a black box behind an SDK; the tensor is built by hand in OnnxU2NetRemover.InferMask. Every constant below is load-bearing — a wrong input name or the wrong normalisation order silently yields a garbage mask rather than an error.

// Engines/OnnxU2NetRemover.cs
private const int    InputSize  = 320;        // fixed square inference resolution
private const float  Mean       = 0.485f;     // ImageNet channel mean
private const float  Std        = 0.229f;     // ImageNet channel std
private const string InputName  = "input.1";  // single NCHW float32 input
private const string OutputName = "1965";     // deepest of U^2-Net's 7 side outputs

// Tensor shape: [1, 3, 320, 320] float32, NCHW, ImageNet-normalised
var tensor = new DenseTensor<float>(input, new[] { 1, 3, InputSize, InputSize });
using var results = session.Run(new[] { NamedOnnxValue.CreateFromTensor(InputName, tensor) });

1 · Down-sample

Nearest-neighbour from source RGBA to 320×320. Cheap and adequate — the mask is re-expanded afterwards anyway.

2 · Normalise

(channel/255 − 0.485) / 0.229 per channel, written into planar NCHW order rather than interleaved.

3 · Clamp, not sigmoid

Output logits are clamped to [0,1]. A sigmoid is skipped deliberately; clamping is what matters before quantising to 0–255 alpha.

4 · Up-sample

The 320×320 mask is nearest-neighbour resized back to full source resolution.

5 · Composite

CompositeMask clones the source RGBA and overwrites only the alpha byte. RGB is never touched by the model.

6 · Then: not the model

Threshold, morphology, feather and the head crop are all deterministic post-processing in EdgeProcessor and HeadFinder.

Re-apply re-runs the model, deliberately

CutoutFileItem.OriginalPngBytes keeps the frame as captured, and re-apply feeds those bytes back through the whole pipeline. Re-cutting the previous cutout would compound each knob change on top of the last. The cost of that correctness is a fresh forward pass per photo on every knob commit.

Telemetry gaps

Three things are not measured anywhere: inference latency, model load time, and request count. CutoutLog.Cutout records output dimensions and byte count but no duration, so there is no in-app signal for “cutouts got slower.” A Stopwatch around engine.RemoveAsync plus a duration parameter on event 2001 would close the gap with no new dependency. Separately, event 2004 can never fire: CutoutService has no job store, so nothing expires — it is a leftover of the deleted multi-step HTTP shape.
