Scope correction

The template traces User Action → Blazor WASM Component → Minimal API Endpoint → Handler → AI Service → Database. Three of those six stages do not exist here: there is no Blazor component, no endpoint, and no database. The equivalent chain that does exist is User Action → XAML Page → ViewModel → Service → Pure logic + ONNX → Disk (only when the user picks a destination), and that is what is traced below, hop for hop.

Tier 1 · Executive summary

30-second read

The whole workflow is: open the page, press TAKE PHOTO, save. The viewfinder starts itself on Loaded, so the button is the only thing to click. Pressing it grabs the most recent preview frame, runs it through decode → ONNX mask → edge clean → head crop → PNG encode, and drops the result into a list. Nothing touches disk until the user picks a destination.

The two design decisions a reader should carry away: the capture is a cached preview frame, not a CapturePhotoToStreamAsync call, because the latter fights the frame reader for the device on many webcams; and the original frame is kept in memory so re-tuning re-cuts from the source instead of compounding knob changes on the previous cutout.

Sequence — payload lifecycle and failure paths

Failure is per photo

A photo that will not process is marked Failed with its own ErrorMessage and stays in the list. ReapplyAllAsync keeps iterating. The batch never aborts — the same rule the chop slice applies to its ZIP.

Cancellation is not failure

Every catch in the chain is written when (exception is not OperationCanceledException). Closing the page cancels the view model’s token and the work unwinds silently instead of painting an error.

The defaults the page ships are not the contract defaults

CutoutOptions defaults to AlphaThreshold = 0, Morphology = 0, TrimPaddingPx = 16. CutoutTuning overrides all three — threshold 160, morphology −1, padding 24 — because those are tuned for a sharp head shot: a hard edge with no feather leaves zero translucent pixels, and the 1 px erode pulls the boundary inside the fringe u2netp leaves around hair. Reading the contract alone will mislead you about what the app actually does.

Two asymmetries worth knowing

Names collide by construction: photo_{Files.Count + 1}.png is recomputed from the current list length, so clearing and re-shooting produces photo_1.png again — and saving both into one folder overwrites the first without warning. (The chop slice solves the equivalent problem properly in ClipExporter.UniqueStems.) Separately, SaveAllToFolderAsync wraps the whole loop in one try, so a failure on file 3 of 10 abandons files 4–10 — unlike the per-file resilience the rest of the app applies.

The knob that makes the chop workflow work

SegmentDetector does not pick a fixed threshold. It sweeps every gate from noiseFloor + 3 dB to peak − 3 dB in 0.5 dB steps and keeps the centre of the widest band of gates that agree on the expected count. A wide band means the split is insensitive to the exact number, which is the definition of a clean split — so the user’s single most useful input is not a threshold at all, it is ExpectedSegments.
